# Front-end Notes

A personal reference built up as we write the app. Each entry should be short and
point at real code in this repo. Written for a backend engineer, so comparisons to
backend concepts are welcome.

## Format

```text
### <Concept>
**What:** one or two sentences.
**Backend analogy:** if there is a useful one.
**In this repo:** path/to/file.tsx (what it does there)
**Gotcha:** the thing that will bite you.
```

## Notes

### PWA (progressive web app)
**What:** a normal website that adds a web manifest (name, icon, full-screen) and a service
worker (offline). Added to the iPad home screen, it opens like an app, without Safari's UI.
**In this repo:** the whole platform ([ADR 001](decisions/001-web-pwa-over-native-ios.md)).
**Gotcha:** on iPad, push notifications only work once it's added to the home screen.

### Compile vs build
**What:** compile = translate one language to another (TS → JS) and check it. Build = the whole
pipeline that produces something deployable: compile, bundle files together, minify, copy
assets, generate the service worker. Vite runs the build; compiling is one step of it.
**Backend analogy:** `javac` vs `gradle build`.

### How a web page works
**What:** the browser fetches HTML and parses it into the **DOM**, a live tree of element
objects in memory. CSS styles the tree; JavaScript can change it at any time. The screen is
just a drawing of the current DOM.
**Backend analogy:** the DOM is like a parsed XML document that code can edit in place.
**Gotcha:** HTML is only the starting tree. In our app it's nearly empty; React builds the rest.

### Who does what
**What:** JavaScript = the language browsers run. TypeScript = JS + static types, compiled to
JS. React = UI library our code calls (in the bundle at runtime). Vite = build tool + dev
server. npm = package manager. Node = runs the tooling on your Mac.
**Backend analogy:** JS ≈ bytecode target, TS ≈ Java, React ≈ Spring, Vite ≈ Gradle,
npm ≈ Maven Central + dependency management, Node ≈ the JVM running Gradle.

### Static vs dynamic typing
**What:** static = variables and functions have declared types, checked *before* running.
Dynamic (JS) = only values have types; nothing checks a function returns what you meant, so
mistakes surface when that line runs. JS is also loose: `"5" * 2` is `10`, `"5" + 2` is `"52"`.
TypeScript adds the static checks; the types are then stripped and plain JS runs.
**Backend analogy:** Java vs old Python. TS ≈ Python type hints + mypy.
**Gotcha:** types are erased at runtime (like Java generics). JSON from the API is not checked
against our `Recipe` type unless we validate it at the boundary.

### SPA vs SSR
**What:** SPA = browser downloads the app once; JS draws each screen and fetches only JSON.
Navigation swaps content in place (no page reload). SSR = a server runs React to send finished
HTML per request (faster first paint, readable by Google), then the browser takes over.
**Backend analogy:** SPA = thick client (desktop app + REST API). Classic server rendering = JSP.
**In this repo:** SPA ([ADR 002](decisions/002-frontend-react-vite.md)): login-only, so no SEO
(search ranking) to win, and the cached app opens instantly anyway.
**Gotcha:** "single page" is about loading, not code. Source is many small component files.

### Front-end hosting vs backend
**What:** the built front-end is **static**: the same files for everyone, served by any file
host/CDN, no app running. The **backend** is a real server: auth, database, private-recipe
checks, and any heavy jobs. Personal data only ever comes from the backend as JSON.
**Backend analogy:** static assets in S3 + your API service.

### Vite: dev vs build
**What:** dev server swaps only the file you saved into the running page (hot module
replacement), keeping state. `vite build` bundles everything into a few files in `dist/`.
**Backend analogy:** `dist/` is the jar. Fast reload comes from the dev server, not the build.
**Gotcha:** some things (e.g. the service worker) only run in the build. Test the build on the iPad.

### Service worker
**What:** a script the browser installs for our site that sits between the page and the
network. It answers requests from a local cache, so the app (and the grocery list) work offline.
**Backend analogy:** a caching reverse proxy (like Varnish/a CDN), but on the device, for one site.
**In this repo:** generated by `vite-plugin-pwa`.
**Gotcha:** updates are sticky: a new version waits until the old one is released. Plan an
update prompt.

### CSS, CSS Modules, Tailwind
**What:** CSS is the styling language. CSS Modules = plain CSS in a file per component, with
class names scoped so they can't clash. Tailwind = a library of tiny classes put directly on
elements (`flex gap-4 p-2`).
**In this repo:** CSS Modules, to learn real CSS layout. Tailwind can be added later.
